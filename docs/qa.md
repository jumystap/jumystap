# Рекомендации по работе с QA

Как разработчику готовить задачу к передаче тестировщику и что учитывать при тестировании этого проекта.

## Отчёт для тестировщика

Пишется в Markdown, вставляется в Jira. Коротко, от первого лица, без деталей реализации (никаких имён классов/методов/энамов) — но **обязательно** с API-контрактом, если он менялся. Рабочий файл называть `<task-id>-report-for-qa.md`; в репозитории храним только образцы в `docs/`.

Структура (пустые разделы не писать):

```markdown
## От разработчика к тестировщику @<тестировщик>

### Что сделано
1–3 строки: суть задачи, что изменилось для пользователя.

### Изменения в API   (только если менялся контракт)
- `METHOD /path` — что изменилось: поля запроса/ответа, валидация, коды ответов (422/403/404/429).
- Ломающие изменения (breaking changes) — выделять явно.

### Инфраструктура    (только если есть)
Фактом, без деталей: новые миграции, env-переменные, пересборка фронта, зависимости.

### Что тестировать
Сценарии из изменений: основной флоу, негативные/граничные кейсы (доступы, лимиты),
регрессы в смежных местах. Известные ограничения — указывать явно, чтобы не ловить их как баги.

### Перед локальным тестированием
Только шаги, реально следующие из диффа:
- composer.json/lock менялись → `composer install`
- package.json менялся → `npm install`; фронт менялся → `npm run build`
- новые миграции → `php artisan migrate`
- .env.example менялся → перечислить КОНКРЕТНЫЕ переменные и что в них писать
- конфиги менялись → `php artisan config:clear`
- очереди/джобы менялись → `php artisan queue:restart`
```

Ориентир — отчёт по задаче «Модерация резюме» (`docs/resume-moderation-report-for-qa.md`).

## Локальный запуск проекта

PHP на хосте нет — всё через Docker:

```bash
docker compose up -d          # app + nginx + mysql + queue + scheduler
npm install && npm run build  # фронт собирается на хосте
```

Прогон тестов — one-off контейнер против отдельной БД `testing` (рабочую `jumystap` не трогает):

```bash
docker run --rm --entrypoint sh --network jumystap_jumystap \
  -v "$PWD":/var/www/html -w /var/www/html \
  -e DB_HOST=mysql -e DB_DATABASE=testing \
  jumystap/app -lc 'php artisan test'
```

Важно: запущенный контейнер `app` собран из образа — правки в рабочей директории он **не видит**, пока образ не пересобран (`docker compose build app`).

## Переменные окружения для тестирования Telegram-функционала

- `TELEGRAM_FEEDBACK_CHAT_ID` — чат, куда уходят формы «Оставить заявку» и «Пожаловаться». Без неё формы отдают ошибку.
- `TELEGRAM_RESUME_MODERATION_CHAT_ID` — чат уведомлений о резюме на модерации. Если пусто — уведомления идут во все зарегистрированные админ-чаты бота (`telegram_admins`, туда попадает любой, кто написал боту `/start`).

Для проверок использовать **тестовый чат/группу**, а не боевой чат модерации. После правки `.env` — `php artisan config:clear` (в Docker — перезапуск контейнера `app`).

## Типовые регрессы проекта (быстрый smoke при любых правках рядом)

- Страница «Сотрудники»: список, поиск, фильтры (профессия/город/с резюме/с сертификатом), пагинация.
- Профиль соискателя: список резюме со статусами, создание/редактирование/удаление, PDF.
- Публичная страница пользователя и детальная страница резюме (включая share-ссылку).
- Вакансии: создание работодателем → модерация → публикация.
- Объявления (маркетплейс): список, модерация в админке.
- Формы «Оставить заявку» и «Пожаловаться» на сайте.
- Админка: разделы Пользователи, Вакансии, Объявления, Резюме; массовые действия и фильтры.
- Локализация: страница переключается ru ↔ kz без «дыр» в переводах.

## Известные особенности окружения

- **Входящие Telegram-вебхуки блокируются сетью хостинга** (тикет у хостера): кнопки «Принять/Отклонить» в Telegram и команды боту не работают, пока блок не снят или не поднят релей. **Исходящие уведомления работают.** Модерация — через админку; это ограничение среды, не баг приложения.
- Тестовая БД `testing` живёт в том же MySQL-контейнере, что и dev-база; тесты используют `RefreshDatabase` и пересоздают её схему.
- Роль пользователя определяет доступ: админка пускает только роли admin/moderator; создание резюме доступно только соискателю (employee).
