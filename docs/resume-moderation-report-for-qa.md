## От разработчика к тестировщику @<тестировщик>

### Что сделано
Резюме теперь проходят модерацию перед публикацией: новое или отредактированное резюме уходит «на модерацию» и не видно на сайте, пока модератор его не одобрит. В админке появился раздел «Резюме»: список с фильтрами, карточка, редактирование, одобрение, отклонение с причиной, массовые действия, история статусов. О новых резюме приходит уведомление в Telegram-чат модерации. Владелец видит статус и причину отклонения в своём профиле. Дополнительно: формы «Оставить заявку» и «Пожаловаться» переведены на отправку через наш сервер (токен бота убран из фронтенда), закрыт доступ к чужим резюме на редактирование/удаление.

### Изменения в API
- `POST /send-telegram-feedback` — новый эндпоинт для форм «Заявка» (`type=application`) и «Жалоба» (`type=complaint`). Поля: `name`, `phone`, `items[]` (профессии/причины), `reason` (для жалобы). Невалидные данные → 422; более 10 запросов в минуту с одного IP → 429.
- `GET /resumes/{id}` и `GET /resumes/download/{id}` — неопубликованное резюме отдаёт страницу «не найдено» всем, кроме владельца и перехода по share-ссылке.
- `PUT /resumes/{id}`, `GET /resumes/update/{id}`, `DELETE /resumes/{id}` — чужое резюме → 403 (раньше можно было открыть/изменить/удалить чужое).
- Админка: `GET /admin/resumes` (список с фильтрами), карточка/редактирование, `POST /admin/resumes/{id}/approve`, `POST /admin/resumes/{id}/reject` (причина обязательна), `POST /admin/resumes/bulk-action`.

### Инфраструктура
- 2 новые миграции. Все существующие резюме автоматически помечаются опубликованными — с сайта ничего не пропадёт.
- 2 новые переменные окружения (см. ниже).
- Пересборка фронта.

### Что тестировать
Основной флоу:
- Создать резюме соискателем → в профиле бейдж «На модерации»; резюме НЕ видно: гостю по прямой ссылке, на публичной странице пользователя, в поиске сотрудников (поиск по должности, фильтр по городу, фильтр «с резюме»), PDF не скачивается.
- В Telegram-чат модерации пришло **одно** уведомление.
- Одобрить в админке → резюме видно на сайте везде; в карточке появилась запись в истории статусов.
- Отклонить с причиной → у соискателя бейдж «Отклонено» и текст причины в профиле; резюме скрыто.
- Соискатель редактирует опубликованное резюме → снова «На модерации», скрыто с сайта, старая причина отклонения исчезла, уведомление пришло. Повторное редактирование, пока резюме на модерации → повторное уведомление НЕ приходит.
- Админ редактирует резюме в админке → статус НЕ сбрасывается. Отклонение через форму редактирования с комментарием → соискатель видит комментарий как причину.
- Массовые действия (одобрить/отклонить/удалить несколько) и фильтры списка (статус, поиск по ID/должности/имени/телефону), пагинация.

Доступы (негатив):
- Обычный пользователь не попадает в `/admin/resumes` (редирект на логин админки).
- Редактирование/удаление чужого резюме → 403; своего — работает.
- Владелец видит своё резюме в любом статусе; share-ссылка открывает неопубликованное резюме.

Формы на сайте:
- «Оставить заявку» и «Пожаловаться» отправляются, сообщение приходит в Telegram-чат, состав полей как раньше.
- Более 10 отправок в минуту → запрос отклоняется.

Регрессы:
- Страница «Сотрудники»: список, пагинация, все фильтры и поиск.
- Профиль: список резюме, создание/редактирование/удаление своих.
- Модерация вакансий не менялась — быстрый smoke.

**Известное ограничение:** кнопки «Принять/Отклонить» в самом Telegram пока не работают — доставка нажатий заблокирована на уровне сети хостинга (решается отдельно с хостером). Модерировать через админку; уведомления в Telegram приходят нормально.

### Перед локальным тестированием
1. `php artisan migrate`
2. `npm run build`
3. В `.env` добавить:
   - `TELEGRAM_FEEDBACK_CHAT_ID=<chat_id>` — **обязательно**: без неё формы «Заявка»/«Жалоба» отдают ошибку
   - `TELEGRAM_RESUME_MODERATION_CHAT_ID=<chat_id>` — чат для уведомлений о резюме; если пусто — уведомления уходят во все зарегистрированные админ-чаты бота
4. `php artisan config:clear`
